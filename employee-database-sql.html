Employee Database — SQL Practice Guide

Practice CREATE, INSERT, UPDATE, DELETE, and SELECT in MySQL using an Employee/Department schema.

1. Logical ER Diagram

The logical model shows entities, attributes, and relationships — no data types or engine-specific detail yet.

erDiagram
    DEPARTMENT ||--o{ EMPLOYEE : "employs"
    EMPLOYEE }o--o| EMPLOYEE : "reports to"

    DEPARTMENT {
        string DepartmentName
        string Location
    }
    EMPLOYEE {
        string FirstName
        string LastName
        string Email
        string Phone
        date DateOfBirth
        date HireDate
        string JobTitle
        decimal Salary
        string Gender
        string Status
    }

Notes

  • One Department employs many Employees (1‑to‑many).
  • Employee has a self‑referencing "reports to" relationship (a manager is also an employee) — many employees report to one manager.

2. Physical ER Diagram

The physical model adds primary keys, foreign keys, exact data types, and constraints — ready to translate into MySQL DDL.

erDiagram
    DEPARTMENTS ||--o{ EMPLOYEES : "DepartmentID"
    EMPLOYEES }o--o| EMPLOYEES : "ManagerID"

    DEPARTMENTS {
        int DepartmentID PK "AUTO_INCREMENT"
        varchar_100 DepartmentName "NOT NULL, UNIQUE"
        varchar_100 Location
    }
    EMPLOYEES {
        int EmployeeID PK "AUTO_INCREMENT"
        varchar_50 FirstName "NOT NULL"
        varchar_50 LastName "NOT NULL"
        varchar_100 Email "UNIQUE, NOT NULL"
        varchar_15 Phone
        date DateOfBirth
        date HireDate "NOT NULL"
        varchar_50 JobTitle
        decimal_10_2 Salary "CHECK Salary greater than 0"
        char_1 Gender "CHECK IN M,F,O"
        varchar_10 Status "DEFAULT Active"
        int DepartmentID FK
        int ManagerID FK "self-reference to EmployeeID"
    }

Physical schema (MySQL DDL)

CREATE TABLE departments (
    department_id   INT AUTO_INCREMENT PRIMARY KEY,
    department_name VARCHAR(100) NOT NULL UNIQUE,
    location        VARCHAR(100)
) ENGINE=InnoDB;

CREATE TABLE employees (
    employee_id   INT AUTO_INCREMENT PRIMARY KEY,
    first_name    VARCHAR(50)  NOT NULL,
    last_name     VARCHAR(50)  NOT NULL,
    email         VARCHAR(100) NOT NULL UNIQUE,
    phone         VARCHAR(15),
    date_of_birth DATE,
    hire_date     DATE NOT NULL,
    job_title     VARCHAR(50),
    salary        DECIMAL(10,2) CHECK (salary > 0),
    gender        CHAR(1) CHECK (gender IN ('M','F','O')),
    status        VARCHAR(10) DEFAULT 'Active',
    department_id INT,
    manager_id    INT,
    CONSTRAINT fk_emp_department FOREIGN KEY (department_id)
        REFERENCES departments(department_id) ON DELETE SET NULL,
    CONSTRAINT fk_emp_manager FOREIGN KEY (manager_id)
        REFERENCES employees(employee_id) ON DELETE SET NULL
) ENGINE=InnoDB;

3. CREATE TABLE Exercises

Exercise 3.1 — Create the departments table with department_id (PK, auto-increment), department_name (unique, not null), and location.

Solution 
CREATE TABLE departments (
    department_id   INT AUTO_INCREMENT PRIMARY KEY,
    department_name VARCHAR(100) NOT NULL UNIQUE,
    location        VARCHAR(100)
);

Exercise 3.2 — Create the employees table with the columns shown in the physical diagram above, including foreign keys to departments and a self-referencing manager_id.

Solution 
CREATE TABLE employees (
    employee_id   INT AUTO_INCREMENT PRIMARY KEY,
    first_name    VARCHAR(50)  NOT NULL,
    last_name     VARCHAR(50)  NOT NULL,
    email         VARCHAR(100) NOT NULL UNIQUE,
    phone         VARCHAR(15),
    date_of_birth DATE,
    hire_date     DATE NOT NULL,
    job_title     VARCHAR(50),
    salary        DECIMAL(10,2) CHECK (salary > 0),
    gender        CHAR(1) CHECK (gender IN ('M','F','O')),
    status        VARCHAR(10) DEFAULT 'Active',
    department_id INT,
    manager_id    INT,
    FOREIGN KEY (department_id) REFERENCES departments(department_id),
    FOREIGN KEY (manager_id) REFERENCES employees(employee_id)
);

Exercise 3.3 — Create a table employee_audit to log salary changes: audit_id (PK), employee_id (FK), old_salary, new_salary, changed_on (defaults to current timestamp).

Solution 
CREATE TABLE employee_audit (
    audit_id    INT AUTO_INCREMENT PRIMARY KEY,
    employee_id INT,
    old_salary  DECIMAL(10,2),
    new_salary  DECIMAL(10,2),
    changed_on  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (employee_id) REFERENCES employees(employee_id)
);

4. INSERT Exercises

Exercise 4.1 — Insert two departments: "Engineering" (Hyderabad) and "Sales" (Mumbai).

Solution 
INSERT INTO departments (department_name, location)
VALUES ('Engineering', 'Hyderabad'),
       ('Sales', 'Mumbai');

Exercise 4.2 — Insert an employee "Anita Rao", email anita.rao@example.com, hired 2023-06-01, job title "Software Engineer", salary 65000, gender F, in the Engineering department (assume department_id = 1), with no manager yet.

Solution 
INSERT INTO employees
    (first_name, last_name, email, hire_date, job_title, salary, gender, department_id, manager_id)
VALUES
    ('Anita', 'Rao', 'anita.rao@example.com', '2023-06-01', 'Software Engineer', 65000, 'F', 1, NULL);

Exercise 4.3 — Insert a manager "Vikram Shah" into Engineering, then insert a new employee "Rohit Verma" who reports to Vikram (use a subquery to look up Vikram's employee_id instead of hardcoding it).

Solution 
INSERT INTO employees
    (first_name, last_name, email, hire_date, job_title, salary, gender, department_id, manager_id)
VALUES
    ('Vikram', 'Shah', 'vikram.shah@example.com', '2020-01-15', 'Engineering Manager', 120000, 'M', 1, NULL);

INSERT INTO employees
    (first_name, last_name, email, hire_date, job_title, salary, gender, department_id, manager_id)
SELECT 'Rohit', 'Verma', 'rohit.verma@example.com', '2024-02-10', 'Software Engineer', 60000, 'M', 1, employee_id
FROM employees
WHERE email = 'vikram.shah@example.com';

5. SELECT Exercises

Exercise 5.1 — List all employees' full name, job title, and salary.

Solution 
SELECT CONCAT(first_name, ' ', last_name) AS full_name, job_title, salary
FROM employees;

Exercise 5.2 — List employees earning more than 60000, ordered by salary descending.

Solution 
SELECT first_name, last_name, salary
FROM employees
WHERE salary > 60000
ORDER BY salary DESC;

Exercise 5.3 — Show each department along with the number of employees and average salary in that department.

Solution 
SELECT d.department_name,
       COUNT(e.employee_id) AS employee_count,
       AVG(e.salary) AS avg_salary
FROM departments d
LEFT JOIN employees e ON e.department_id = d.department_id
GROUP BY d.department_name;

Exercise 5.4 — List every employee together with their manager's name (self-join).

Solution 
SELECT e.first_name AS employee_first_name,
       e.last_name  AS employee_last_name,
       m.first_name AS manager_first_name,
       m.last_name  AS manager_last_name
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.employee_id;

6. UPDATE Exercises

Exercise 6.1 — Give every employee in the Engineering department a 10% raise.

Solution 
UPDATE employees e
JOIN departments d ON e.department_id = d.department_id
SET e.salary = e.salary * 1.10
WHERE d.department_name = 'Engineering';

Exercise 6.2 — Mark employee "Rohit Verma" as Inactive in the status column.

Solution 
UPDATE employees
SET status = 'Inactive'
WHERE email = 'rohit.verma@example.com';

Exercise 6.3 — Reassign all employees who report to Vikram Shah to a new manager, "Anita Rao", using subqueries for both lookups.

Solution 
UPDATE employees
SET manager_id = (SELECT employee_id FROM employees WHERE email = 'anita.rao@example.com')
WHERE manager_id = (SELECT employee_id FROM employees WHERE email = 'vikram.shah@example.com');

7. DELETE Exercises

Exercise 7.1 — Delete the audit log entries older than 2 years.

Solution 
DELETE FROM employee_audit
WHERE changed_on < NOW() - INTERVAL 2 YEAR;

Exercise 7.2 — Delete a specific employee by email, e.g. a test record test.user@example.com.

Solution 
DELETE FROM employees
WHERE email = 'test.user@example.com';

Exercise 7.3 — Delete all employees whose status is Inactive and who have no direct reports (i.e., no one lists them as manager). Explain why order matters with foreign keys.

Solution 
DELETE FROM employees
WHERE status = 'Inactive'
  AND employee_id NOT IN (
      SELECT DISTINCT manager_id
      FROM employees
      WHERE manager_id IS NOT NULL
  );

Note: Because manager_id is a self-referencing foreign key, MySQL will block deletion of an employee who is still referenced as someone else's manager (unless the FK has ON DELETE SET NULL, as defined in the schema above). The NOT IN subquery avoids that conflict by only deleting employees nobody currently reports to.

  3. Practice SELECT queries to verify your data (Section 5).
  4. Practice UPDATE statements, then re-run relevant SELECTs to confirm (Section 6).
  5. Practice DELETE statements last, since they affect the data used above (Section 7).
